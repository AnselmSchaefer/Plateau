# Plateau's modules

Made from the code by `engine/tests/docs.rs`, never by hand: each crate's modules, what each says it is (its first comment's first sentence), and which modules it uses (in its own crate, and `engine::`/`sdk::` across crates). `PLATEAU_KEEP=1 cargo test -p plateau-engine --test docs` writes it again; the test fails while it is stale. The concepts are in `ARCHITECTURE.md`.

## plateau-sdk (`sdk/`)

| Module | What it is | Uses |
|---|---|---|
| `bindings` | Generated by `wit-bindgen` 0.63.0. | `rt` |
| `lib` | Everything an area's program needs (POC_PLAN.md, step 1). | `bindings`, `mesh`, `rt` |
| `mesh` | Open procedural mesh & scene workshop for Plateau areas (`plateau_sdk::mesh`). |  |
| `rt` | What the generated bindings (`bindings.rs`, made with `--runtime-path crate::rt`) need of a runtime: wit-bindgen's own, cut down to this one world, so a theme's build needs no crate but this one. |  |

## plateau-engine (`engine/`)

| Module | What it is | Uses |
|---|---|---|
| `atlas` | Multi-area world atlas & seamless border stitching (POC_PLAN.md, step 9). | `chunk`, `compose`, `reach`, `scene` |
| `body` | A player's body (POC_PLAN.md, step 2): a capsule as tall as the player's size, colliding with the area's distances asked at that size, walking, jumping and sitting, growing and shrinking. | `chunk`, `math` |
| `check` | The engine's check of an area's module, every time it is loaded, never trusted (POC_PLAN.md, step 1): what it may import and must export, its memory, and the WebAssembly it may use. |  |
| `chunk` | Chunks of an area's surface (POC_PLAN.md, step 2, "Meshing"): surface nets over a cube of `CELLS` cells a side, asked of the area at the size the chunk's voxel is detail for. |  |
| `compose` | Composable standalone `.wasm` elements (POC_PLAN.md, step 8b; AGENTS.md). | `chunk`, `cut`, `edit`, `math`, `mesh_sdf`, `modules`, `scene`, `wasm`, `water` |
| `cut` | Deterministic procedural `Scene` cutting, watertight cross-section capping, and scale-aware object physics / carry limits (Step 8c; AGENTS.md §1.3 & §2). | `compose`, `edit`, `physics` |
| `edit` | Scale-stamped SDF sculpting & digging overlay (POC_PLAN.md, step 8; AGENTS.md). | `chunk`, `compose`, `cut`, `modules`, `rules`, `water` |
| `fit` | Whether an element fits the site it is for (Phase C): the laws a site-made element is held to, and where a carried one (a round door of any size) goes to fit an opening. | `body`, `compose`, `laws`, `mesh_sdf`, `scene`, `site` |
| `laws` | The laws an area must keep (CONCEPT.md, "Laws"; POC_PLAN.md, step 3), searched for rather than proved. | `atlas`, `chunk`, `reach`, `rings`, `sketch`, `wasm` |
| `lib` | Plateau's engine (POC_PLAN.md). | `atlas`, `compose`, `cut`, `edit`, `fit`, `mesh_sdf`, `modules`, `physics`, `rules`, `site`, `wasm`, `water`, `world` |
| `live` | The live world (`WORLD_PLAN.md`, phase E): everything a world is while someone plays it, and every change to it. | `atlas`, `body`, `chunk`, `compose`, `cut`, `edit`, `math`, `modules`, `physics`, `rules`, `scene`, `water` |
| `live::action` | What a player asks of the world, and what came of it (`WORLD_PLAN.md`, phase E). | `body`, `compose`, `cut`, `edit`, `physics`, `rules`, `water` |
| `live::history` | Undo and redo (`WORLD_PLAN.md`, phase E): what each change did, kept so it can be undone, across sculpting, promotion, placing, chopping and moving. | `compose`, `edit` |
| `live::log` | The action log (`WORLD_PLAN.md`, phase E): one JSON line an action, so a session can be read (by people, by the inspector of phase K) and replayed (`replay`) onto the save it began from. | `body` |
| `live::objects` | Changes to placed objects (`WORLD_PLAN.md`, phase E): chopping, carrying, setting down, and piloting what floats. | `body`, `compose`, `cut`, `math`, `physics`, `rules` |
| `math` | The engine's own transcendental functions (`WORLD_PLAN.md`, phase D). |  |
| `mesh_sdf` | Exact, deterministic, BVH-accelerated Signed Distance Field built from a procedural `Scene`'s solid triangle meshes (`MeshSdf`). |  |
| `modules` | Which modules a saved world was made of (`WORLD_PLAN.md`, phase D). | `edit` |
| `physics` | Material physics table, tool-material interaction capabilities, and Archimedes buoyancy for floating & navigable procedural `Scene` objects (Phase B; AGENTS.md §1.3 & §2). | `chunk`, `compose`, `cut`, `math` |
| `picture` | Pictures of an area, ray-marched on the CPU from its own answers, headless (POC_PLAN.md, "Pictures", step 4): the same on any machine, in tests, and for Claude to be shown. | `atlas`, `body`, `reach` |
| `reach` | Where each size can go (POC_PLAN.md, step 3): the places a body of each size can stand, and the ways between them, searched from the area's start. | `body`, `chunk` |
| `rings` | Which chunks a viewer sees (POC_PLAN.md, step 2): the finest about them, coarser further off; and, while some are still being made, which to show instead. | `chunk`, `math` |
| `rules` | Multi-scale ownership & permission Rule Book (Phase A). |  |
| `scene` | Runtime procedural scene state, multi-layer composable element isolation, dynamic instance collision, and crosshair targeting. | `compose` |
| `site` | Site & cavity measurement (Phase C; AGENTS.md §1, §2). | `body`, `chunk`, `compose`, `laws` |
| `sketch` | A sketched map of an area, from above (CONCEPT.md, "The sketch"; POC_PLAN.md, step 6): drawn in any paint program on a white background with the seven pens of `sketches/plateau.gpl`, north at the top (z = 0) and east to the right (x = 64). |  |
| `wasm` | An area's module in wasmtime, with the limits the engine keeps (POC_PLAN.md, "Running areas"): fuel for each batch, a memory limit, no SIMD and no threads, NaNs left as the machine makes them (the law `laws::nans_unseen` stands in for making them one). | `check` |
| `water` | Engine-managed hydrostatic water bodies & dynamic pond expansion (Phase A). | `chunk`, `edit` |
| `world` | A saved world opened without a window (Phase C): its areas, sculpting, water and placed elements, made again from the save as the player has them, for measuring sites in it (`site`), judging what is made for them (`fit`), and picturing both (`picture`). | `atlas`, `compose`, `edit`, `modules`, `scene`, `water` |

## plateau-play (`play/`)

| Module | What it is | Uses |
|---|---|---|
| `carry` | Interactive carrying, rotating/tilting, drop preview ghost, and felled-object topple animation in `plateau-play` (Step 8c; AGENTS.md §1.3). | `surface`, engine::`compose`, engine::`cut` |
| `chunks` | The area's surface about the player, made off the frame (POC_PLAN.md, steps 2, 7, and 8): view-directed `6×4×6` rings shifted forward along the look direction, frustum-prioritized chunk streaming, complementary 4×4 Bayer dithered LOD cross-fades, and live targeted chunk invalidation for scale-stamped SDF edits & placed SDF `.wasm` elements with zero-flicker in-place mesh swaps. | `surface`, engine::`atlas`, engine::`chunk`, engine::`compose`, engine::`live`, engine::`picture`, engine::`rings` |
| `figure` | The player, seen: a figure of a person drawn where the body is, walking, running, jumping, falling, sitting and standing as the body does, and turning to face the way it goes. | engine::`body` |
| `flags` | Flags over the places for the tiny, to find them by: what is meant for the tiny is too small to see from any distance, while a giant's place (a seat 4.5 m up) is plain to see. | engine::`body`, engine::`picture` |
| `main` | Plateau, played (POC_PLAN.md, steps 2, 7, 8, and 9): one or more areas stitched side by side, walked at three sizes, the player seen from behind (`figure`) or through their own eyes, with live multi-scale SDF sculpting (`B`), composable standalone `.wasm` element placement (`P`), and physical chopping (`K`) & carrying (`G`). | `carry`, `chunks`, `figure`, `flags`, `place`, `scene`, `sculpt`, `surface`, `trace`, engine::`atlas`, engine::`body`, engine::`cut`, engine::`edit`, engine::`fit`, engine::`laws`, engine::`live`, engine::`modules`, engine::`rings`, engine::`rules`, engine::`scene`, engine::`site` |
| `place` | Interactive standalone `.wasm` element placement, cavity fitting & preview ghost in `plateau-play` (Step 8b / Phase C). | `scene`, engine::`compose`, engine::`live`, engine::`site` |
| `scene` | Multi-layer GPU procedural scene renderer & runtime sync (`Scene` / `SceneWorld`). | `surface`, engine::`compose`, engine::`picture`, engine::`scene` |
| `sculpt` | Live multi-scale SDF sculpting & digging in `plateau-play` (POC_PLAN.md, step 8a). | engine::`edit`, engine::`physics`, engine::`picture` |
| `surface` | Chunk and prop surface material (POC_PLAN.md, step 7): extends Bevy's `StandardMaterial` with a 4×4 Bayer dithered LOD cross-fade and world-locked procedural micro-grain + glossy water. |  |
| `trace` | `--trace <file>.json` (`WORLD_PLAN.md`, phase E): the engine's spans (an action applied, its rule and tool checks, promotion, water, commits) written as Chrome trace events, to be read in the Perfetto UI (ui.perfetto.dev) or `chrome://tracing`. |  |
